How It Runs

The pipeline behind every notification

This is real, running infrastructure — a scheduled GitHub Action checks official sources, detects real changes, and delivers a notification through Firebase.

  1. Official Source — the institute's real website.
  2. Scheduler — a GitHub Action, running on a fixed schedule.
  3. Change Detection — compares against the last known version, stored in Firestore.
  4. Notification Engine — matches the change to subscriptions and sends a push notification via Firebase Cloud Messaging.
  5. You — get notified the moment it's official.

Frequently Asked Questions

Common questions about tracking

What does "tracking" actually mean on Trackly?

Subscribing to one specific official update so Trackly can tell you the moment it changes, instead of you checking manually.

Is this update being tracked right now?

Yes, once your Trackly deployment is fully set up. A scheduled GitHub Action checks the official source and compares it against the last known version stored in the database.

How will Trackly know when something changes?

By checking the institute's own official source on a regular schedule and comparing it to the last known version.

Will Trackly ever guess a date or result?

No. Trackly only reports what the official source has actually published.

How will I be notified?

Through a browser push notification, via Firebase Cloud Messaging — turn it on from this page once you're tracking something, or any time from your dashboard.

Can I track more than one update at a time?

Yes. Every tracker you subscribe to, for any institute, appears in your dashboard under My Trackers.

Does tracking cost anything?

No. Tracking updates is free in Version 1.

What happens after I click "track" today?

You'll be asked to log in (if you aren't already), and your subscription is saved immediately. From then on, the monitoring Action checks this source on schedule — no need to keep the site open.
